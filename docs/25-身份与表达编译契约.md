# 统一规则解析与稳定身份契约（V2.1 Draft）

> 用户可以调整图纸列表、图号、图框、纸张及视口布局，但这些调整不得造成智能构件丢失或索引失效。
> 机器数据：`data/drawing-sheet-identity.v2.1.json` 和 `data/presentation-plan-contract.v2.1.json`。

## 四种身份

| 类型 | 示例 | 是否永久稳定 | 对应内容 |
|---|---|---|---|
| `drawingTypeId` | `INT-LAYOUT` | 是 | 逻辑图纸类型 |
| `drawingUid` | UUIDv5 | 是（单个项目内） | 具体内容，如某柜体东立面 |
| `sheetUid` | UUIDv4 | 是（该物理页生命周期） | A3/A2布局及图签 |
| `viewportUid` | UUIDv4 | 是（该视口生命周期） | 图纸内容在纸上的一次放置 |
| `sheetNo` | `D-03` | **否** | 人可读图号、编排顺序 |

原始V2.1编译器把稳定的“图纸内容实例”错误地命名成`sheetUid`。现已将其明确更名为`drawingUid`，单纯根据图纸目录生成的逻辑条目，`sheetUid`先保持null，必须在纸面编排阶段才赋值。旧`S-001`只是预览顺序，不可用于长期引用。

智能构件必须有独立对象UID；DWG Handle只能作为当前文件定位线索，不能跨DWG复制/迁移当作全局唯一ID。

## PresentationPlan：规则编译器的唯一输出

输入：规范版本摘要、项目/图纸内容/纸张页/视口UID、业务对象属性、实际几何包络、目标输出模式、`dryRun`。

输出：
1. 所采用的图框、图签与槽位、建议布局和视口比例；
2. 哪些业务对象与表达角色显示、弱化或隐藏；
3. 解析后的图层、对象线宽和视口覆盖、命名STB样式；
4. 遮罩对象归属与有效足迹、局部绘制顺序边；
5. 图纸间索引与影响依赖，以及图签的页码/修订/多比例标签；
6. `diagnostics`（致命错误、需人工复核、可接受信息）和`ruleTrace`（每个结果源于哪一条版本化规则）；
7. `applyReady=false`直到规则配置、二进制资产、真实CAD状态均满足验收门槛。

目标是**同一套解析内核服务CLI、管理页面与CAD插件**，而不是三个模块各读各的JSON、产生不一致解释。

## 跨图纸影响图

例：智能柜体移动可直接更新布局表现；柜体立面和抽屉尺寸也许需要重新生成；附近插座是否调整则列入“人工复核”，不能直接决定施工。

对象变更应关联`drawingUid`，再反查这个图纸内容出现在哪些`sheetUid`的`viewportUid`，并生成影响报告。单张图纸可以跨多个纸张复用，因此**不能只按图号查受影响页**。

## 版本与仓库数据边界

SQLite管理库是草稿工作区，GitHub审核发布的JSON快照才是正式规范；插件只读取本地已发布快照与项目索引库，离线无需本地管理服务常驻。

规范SQLite和项目索引SQLite分离：
- `schema/standard-management-v2.1.sql`：标准目录、图框、视口与规则。
- `schema/project-sheet-index-v2.1.sql`：项目逻辑图纸、物理页、视口、构件依赖与跨图纸引用。只提供结构，不存真实客户资料。

当前仅有dry-run图纸目录与排版求解示例，**尚未实现完整Presentation Resolver/CAD执行器**。
