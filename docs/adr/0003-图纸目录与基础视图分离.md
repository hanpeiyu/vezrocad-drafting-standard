# ADR-0003：SheetSet 图纸目录与基础视图分离

- 日期：2026-11-12
- 状态：**Proposed / 未接受**
- 对应：`docs/17-家装图纸分类与交付目录.md`、`docs/18-各专业图纸表达矩阵.md`

## 问题

旧 `data/view-presets.json` 只有九个基础视图；实际家装施工图有更多图纸，且多个图纸可能共用同一基础视图但强调不同对象。因此把所有图纸当作一个“视图类型”会导致暴涨的重复配置，且无法编排图纸目录、实例、条件和输出。

## 提案

1. 保留九个基础视图模板，用于图形表达的基础显示。
2. 新增稳定 SheetType 目录；定义专业组、图纸实例、条件触发、可重复实例、输出默认值及人工校核。
3. 新增独立 SemanticTag 与 SheetExpression；不强制一标签对应一个 CAD 图层。
4. 以 ProjectScope 构建 SheetSet，再为每张 SheetInstance 解析图形、线宽与输出模式。
5. 未知语义及无法满足的工程条件报警而不自动隐藏、猜测或生成虚假施工信息。

## 替代方案

- 仅扩展 `view-presets.json` 到三四十个：容易重复且缺图纸编排能力。
- 一个图纸类别固定绑定一张 DWG：无法共享几何，修改时同步成本高。
- 把图纸编号写死在族对象里：同一对象无法参与多张图纸，破坏智能构件架构。

## 合并条件

CAD 端所有执行操作都是可预览、可撤销的；同一数据能生成多张视图表达；图纸集由项目条件真正驱动；电气等专业审核不会被图纸生成器绕过；A3 实际 PDF 通过后才可对外称作施工图可用。

当前仅是规范与 dry-run 演示，没有正式生成 DWG 或 PDF。
