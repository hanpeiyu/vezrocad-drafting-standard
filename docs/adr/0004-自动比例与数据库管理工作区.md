# ADR-0004：图纸自动适配比例与关系数据库编辑工作区

- 日期：2026-11-12
- 状态：**Proposed / 未接受**
- 涉及：打印比例、自适应图纸套、SQLite管理库、WebView2管理界面

## 问题

V2.1初稿将不同图纸的比例写为默认值，但同样的A3纸在户型外包框很大、图签与标注占用纸面时放不下。越来越多的图层、图纸类型、语义角色和打印规则也不适合长期手工编辑散落的JSON。

## 推荐方案

1. 图纸类型只定义“首选比例 + 可选比例”，实际纸张和比例由实例内容外包框与真实可打印净区域计算。
2. 允许A3优先、A2/A1备选；或拆成总图与局部放大图，不能无限缩小以塞进一页。
3. 纸面线宽由最终比例的预设控制（VP Lineweight），与STB打印色彩解耦。
4. 标准库采用Git审阅/发布的规范快照为权威数据；SQLite用于本地草稿编辑、FK关系校验和管理页面查询。
5. React+TypeScript在WebView2中充当管理UI；插件仍可离线读取固定版本JSON，不依赖SQL服务常驻。
6. 项目实际DWG几何和工程数据与规范库分离；必要时再做项目索引数据库。

## 被否决的替代方向（待讨论）

- 把所有家装施工图永久固定1:50：大户型溢出、节点不清晰。
- 以每种纸张×每种比例×每种专业生成多份STB：组合爆炸、难版本控制。
- 插件直接实时查询唯一远程SQL服务器：离线不可用，插件性能及权限耦合过高。
- 把所有几何和构件属性从DWG迁入标准数据库：失去CAD原生编辑和可移植性。
- Git和SQLite两个系统都可以直接发布：出现双权威与难复现的版本漂移。

## 验收条件

1. 10个比例适配样例和SQLite外键脚本通过结构校验。
2. 真实CAD2027中读取图框净区、正确保留注释、旋转时不破坏指北及关联。
3. 没有几何外包框时必须给出“未校验”，不能假称默认比例可打印。
4. 同一房屋多幅面、多比例图纸可同时输出，模型真实尺寸不变。
5. 管理器编辑数据库不能自动改变生产规范，发布须PR/版本/可回滚。
6. 不包含或公开客户真实CAD与商业文件。

**尚未形成生产级数据库、Web管理页面和CAD端自动选比例执行器。**
